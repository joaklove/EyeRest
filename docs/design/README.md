# EyeRest 视觉基准（Design Source of Truth）

## 唯一视觉基准

`reference/方案三-轻奢艺术-温暖治愈.jpg`（1312×1199）

**本目录是 EyeRest UI 的唯一视觉 Source of Truth。** 任何 AI（Claude Code / Codex / Trae / WorkBuddy）或人接手 UI 工作前，必须先读这张图，**禁止凭文字描述"方案三是什么"**。

> ⚠️ 文件是 `.jpg` 而非 `.png`，因为落地来源是系统剪贴板缓存（粘贴的图片会被剪贴板管线重编码为 JPEG）。
> **2026-09-11 复核**：用户再次提供了"原始 PNG"，但经剪贴板落地后与既有文件 **MD5 完全相同**（`4ee40332930f42ed10a299fb5aa473f5`，225444 字节），即仍是同一份 JPEG，不是无损原图。
> JPEG 有压缩噪声，会影响像素级取色精度（平坦色块 ≤±3/255）。**如手头有真正未经重编码的 PNG 文件，请直接拷贝到 `reference/` 目录（不要用粘贴），并在下表中标注取自 PNG。**

## 取色实测 v2（2026-09-11，定稿版）

### 采样方法（可复现）

1. 原图 `reference/方案三-轻奢艺术-温暖治愈.jpg`（1312×1199，JPEG 质量≈85，量化表 `[5,3,3,5,7,12,15,18]`）。
2. 在 y=530 行做水平扫描，按「与白底差异 >25」切出连续段 → 定位「配色方案」四个色卡圆的圆心：
   `x = 982 / 1069 / 1156 / 1243`（间距 87px，等距）。
3. 对每个圆心先纵向扫描确定真正的圆心 y（512–545），再取**核心区 17×13 像素的中值**（中值而非均值，避开抗锯齿与 JPEG 振铃）。
4. 交叉验证：另外采样界面上的**大面积实色品牌绿**（实心按钮、标题胶囊、滑杆填充、Toggle），与色卡互证。

### 结果（四张色卡同一方法）

| 色卡 | 板上的 hex 标注 | **实画采样** | H | S | V | ΔRGB（实画−标注） |
|---|---|---|---|---|---|---|
| 主色 | `#4CAF8A` | **`#26AE89`** | 163.7 | 78.2 | 68.2 | **(−38, −1, −1)** |
| 辅助色 | `#F8F5EF` | `#FBF4EC` | 32.0 | 6.0 | 98.4 | (+3, −1, −3) |
| 强调色 | `#FFD6A8` | `#FDD49B` | 34.9 | 38.7 | 99.2 | (−2, −2, −13) |
| 文字色 | `#2D3748` | `#373F4F` | 220.0 | 30.4 | 31.0 | (+10, +8, +7) |

**关键发现（v1 结论的修正）**：v1 曾笼统地说"图上标注不可信"。用同一方法测完四张色卡后可以看到——**辅助色 / 强调色 / 文字色 的标注都是准的**（ΔRGB 在 JPEG 噪声量级内），**只有主色的标注失真**，且失真方式是 R 通道偏高 38：标注 `#4CAF8A` 比实画淡得多（S57 vs S80）。

结论：**不要因为"AI 标注不可信"就整体打折，而应逐色判定**——本次只有主色需要改。

### 主色交叉验证（界面上的大面积实色）

| 位置 | 采样值 | H | S | V |
|---|---|---|---|---|
| 配色方案「主色」色卡圆 | **`#26AE89`** | 163.7 | 78.2 | 68.2 |
| 「保存位置」实心按钮（位置编辑弹窗） | `#15A67C` | 162.6 | 87.3 | 65.1 |
| 「方案三」标题胶囊底 | `#29A180` | 163.7 | 74.3 | 63.1 |
| 「呼吸」滑块已填充段 | `#339578` | 162.6 | 65.8 | 58.3 |
| 全图最饱和 10% 像素均值 | `#15A27C` | 163.8 | 87.0 | 63.5 |
| 色相直方图峰值簇（S70–80） | `#2C9D7F` ~ `#26A782` | 164 | 72–80 | 62–66 |

**六路独立采样全部落在 H 162.6–164.0 区间**，色相高度收敛 —— 色相是本次最可靠的结论（S/V 对 JPEG 敏感，色相对大面积平坦区几乎免疫）。

### 定稿：主色 `#26AE89`

| 项 | 旧 tokens | 实测 | 偏差 |
|---|---|---|---|
| 色相 H | 171.4° | 163.7° | **偏青 7.7°** |
| 饱和度 S | 62.4% | 78.2% | **偏淡 15.8 个点** |
| 明度 V | 79.2% | 68.2% | **偏亮 11 个点** |

这就是"我们的绿是薄荷青、板上的绿是植物绿"的量化原因，三项偏差方向一致（更青 + 更淡 + 更亮）。

**v1 的「折中值」方案已废弃**：v1 推荐 `#35B18C`（S70），理由是"AI 渲染偏艳、大面积会刺眼"。但本次新增了第二组独立证据——**实心按钮 S87、全图最饱 10% 均值 S87**，说明设计稿里的大面积实心绿本来就是高饱和的，不是渲染事故。因此**直接对齐色卡实画值 `#26AE89`**，不再人为降饱和。

> 备注：设计稿的实心 CTA 按钮（`#15A67C`，S87 V65）比色卡主色更深一档。这是设计稿里真实存在的两级绿（品牌绿 / CTA 深绿）。本次先把 `PRIMARY` 对齐到色卡品牌绿；若后续要逐像素贴合按钮，可再引入 `PRIMARY_DEEP = #15A67C`。

### 精度声明

- 底图是 JPEG q85（粘贴经剪贴板被重编码），**平坦色块误差 ≤ ±3/255**，色相误差 ≤ ±1°。
- 因此本报告的**色相结论可直接采用**；S/V 保留到整数个百分点即可，不要追求小数位。
- ⚠️ 若后续拿到**真正的原始 PNG**（未经剪贴板重编码），可复核一次；方法同上，预期与本文一致；如不一致以 PNG 为准。

## 目录规约

```
docs/design/
├── README.md          本文件
├── reference/         唯一视觉基准（只读，不要改图）
└── acceptance/        多状态验收截图留档
                       命名：页面-状态[-备注].png
                       例：home-正常.png / home-英文-125dpi.png

tools/
└── render_theme_compare.py   配色改动的前后对比渲染（见「使用规则」4）
```

## 使用规则

1. 展示板是唯一视觉基准；**图上的文字标注不作为色值来源**，一律以像素采样为准。
2. 展示板未覆盖的状态（英文、空数据、暂停、125% DPI），以 `../UI_ROUTE_EVALUATION.md` §10 的多状态矩阵为验收依据。
3. 每次 UI 迭代的验收截图存入 `acceptance/`，命名遵循上述格式。
4. 改配色（tokens / SVG）后，用 `tools/render_theme_compare.py` 出前后对比图：

   ```bash
   .venv/Scripts/python.exe tools/render_theme_compare.py after
   git stash push -- app/ui/theme/tokens.py app/ui/visual_cue.py app/assets/illustrations
   .venv/Scripts/python.exe tools/render_theme_compare.py before
   git stash pop
   ```

   截图工具 `.build/render_ui.py` 出四个页面；四页截图 + 对比图一并归档到 `acceptance/`。
5. **渲染截图必须用默认 windows 平台**，不要设 `QT_QPA_PLATFORM=offscreen`——offscreen 下 CJK 字形缺失会渲染成方块，会误导判读。
